# 技术架构（MVP）

## 1. 总体架构

采用“前后端分离 + AI 网关 + 可观测”架构：

1. Client（Web/H5）
2. BFF/API 层（鉴权、聚合、限流）
3. Domain 服务层（内容、导览、路线、生成、后台）
4. Data 层（PostgreSQL、Redis、对象存储）
5. AI 层（LLM、TTS、图像生成）
6. Observability（日志、指标、链路追踪、告警）

## 2. 领域边界

### 2.1 内容域 Content
- 非遗项目、知识段落、标签、素材管理
- 审核发布流与版本控制

### 2.2 导览域 Guide
- 导览脚本模板
- AI 生成编排（提示词 + 约束 + 兜底）
- 上下文会话状态

### 2.3 路线域 Route
- 推荐引擎（规则 + 轻量打分）
- 路线编辑与重算

### 2.4 生成域 Generate
- 海报模板渲染
- 用户素材处理
- 下载与分享链接管理

### 2.5 运营域 Admin
- 后台权限与审计
- 数据看板与导出

## 3. AI 可控策略

1. Prompt 分层：系统约束 / 任务指令 / 数据上下文
2. RAG 预留：通过 `heritage_contents` 片段检索注入
3. 输出验证：JSON Schema 校验 + 敏感内容过滤
4. 事实保护：仅允许引用白名单字段
5. 失败兜底：返回规则稿并提示“智能讲解暂不可用”

## 4. 安全架构

- 鉴权：JWT（Access + Refresh）
- 授权：RBAC（游客、注册用户、运营、管理员）
- 数据保护：敏感字段加密 + 传输 HTTPS
- 上传安全：病毒扫描（可选）+ MIME/后缀双检
- 审计：后台关键操作写入 `audit_logs`

## 5. 可观测设计

- 日志：结构化 JSON，统一 request_id / user_id
- 指标：接口耗时、错误率、AI 调用耗时与失败率
- 追踪：OpenTelemetry 全链路追踪
- 告警：5xx、延迟、外部依赖故障

## 6. 部署建议

- 环境：dev / staging / prod
- 交付：Docker + CI/CD
- 灰度：功能开关与分批发布
- 备份：数据库每日备份 + 对象存储生命周期
